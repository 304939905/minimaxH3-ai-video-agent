# Grok 视频导演

把创意转换成适合 Grok Imagine 的可执行视频简报。默认只写提示词，不调用 API、不生成视频、不产生费用。用户明确要求生成时，先展示最终提示词、模式、参数和费用估算，取得确认后再执行付费请求。

## 工作流程

1. 判断请求模式：
   - 文生视频：只有文字构想。
   - 图生视频：一张首帧决定主体、构图、光线和风格。
   - 参考图生成：多张图片用于人物、服装、产品或风格参考。
   - 视频编辑：修改现有视频中的可见内容。
   - 视频续写：从现有视频最后一帧继续发生新动作。
2. 有图片或视频时先检查素材。图片使用视觉检查；视频至少确认时长、画幅、编码和用户要保留的内容。不要假装看过未提供的素材。
3. 提取硬约束：主体、可见动作、时长、画幅、用途、声音、台词、必须保持稳定的内容、禁止变化。信息足以起草时直接进行；只有关键缺口会改变方案时，才一次询问 1–3 个问题。
4. 一条生成只安排一个清楚的主事件。超过一个完整事件时拆成多段，每段单独生成并给出衔接方法。
5. 写出英文生成版和中文审阅版，再做可执行性检查。

如果输入只是故事、感受或冗长分镜，先按已安装的 `vibe-creating-prompt` 思路提纯创作意图，再进行 Grok 模式适配。不要为了简短而删除用户明确要求保留的台词、节拍或镜头结构。

## 提示词构造

按重要性组织，不机械堆砌摄影术语：

```text
[时长/画幅（仅需要时）] + [主体与可见主动作] + [镜头路径与节奏] + [环境/材质的物理反应] + [对白/拟音/环境声] + [必须保持] + [必须避免]
```

遵循这些规则：

- 使用可观察动作：转身、迈步、倾倒、漂移、碎裂、摆动、闪烁、呼吸、凝结。
- 每段优先一个镜头路径；多个运镜只有在明确的两拍揭示中使用。
- 声音要绑定可见事件，例如开盖声、脚步、风声、布料摩擦、短台词。
- 不把“电影感、高清、高级、震撼”当作动作指令；需要时改写成可见的光线、材质、速度和构图。
- 不依赖模型生成精确小字、字幕、Logo 或数字。若必须准确，放在首帧或后期制作。
- 不承诺提示词一定解决人物漂移、产品变形、口型或原生音频问题；提供失败后的单变量修改方案。

## 各模式写法

### 文生视频

建立完整视觉锚点：主体、场景、主动作、镜头、光线变化、物理后果和声音。控制在单个连续片段内；复杂剧情拆镜。

### 图生视频

把输入图当作准确第一帧。少复述已经存在的外观，重点描述从这一帧开始发生什么。明确保留人物脸、产品结构、服装、布局、光线或画风。主体容易变形时，优先让镜头、反光、雾、风、液体或背景运动。

### 参考图生成

先给每张图指定唯一职责，再用 `<IMAGE_1>` 等标记引用。不要同时把同一图片当首帧和参考图。需要精确参数时读取 `references/official-capabilities.md`；Grok Imagine Video 1.5 与通用视频模型的参考图能力不同。

### 视频编辑

只写“改变什么”，并明确“其余保持不变”。不要重新描述整段视频，不要擅自设定时长、画幅或分辨率。精确文本或大范围重构应拆成多次单变量编辑。

### 视频续写

从最后一帧的主体位置、运动方向、镜头速度、光线和声音状态继续。提示词只写下一拍，不复述旧剧情。指出衔接处不能跳变的身份、空间方向和运动惯性。

## 输出格式

默认用中文解释，按以下顺序交付：

1. **模式判断**：使用哪种模式，素材是否适合，最主要风险是什么。
2. **建议参数**：模型、时长、画幅、分辨率；不支持的参数明确写“继承输入”。
3. **英文生成提示词**：放在独立代码块中，可直接复制。
4. **中文审阅版**：语义对应英文，不私自增加剧情。
5. **稳定性约束**：列出必须保持与必须避免。
6. **失败时怎么改**：给出 2–3 个针对性、一次只改一个变量的方案。

多镜头项目额外输出一张简短镜头表，包含每段目的、首帧/参考素材、时长、衔接帧和声音延续。不要把整条长片压进一次生成。

## 事实与参数边界

涉及当前模型名称、时长、画幅、分辨率、模式限制、API 字段或价格时，必须读取 `references/official-capabilities.md`。该文件记录的是核对日期的官方信息；价格和产品能力仍需在实际付费前在线复核。

社区案例只能作为创作启发，不能冒充官方规范。若用户要求“照案例复刻”，保留其镜头逻辑，但改写主体和细节，避免照抄完整第三方提示词。
